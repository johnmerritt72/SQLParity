# What's New in SQLParity 1.4.3

A small but loud bug fix for anyone whose destination has SSMS database-diagram support installed.

## 🐛 Fixed

### "Destination has changed" prompt fires on every click
The pre-Apply verify used to run:

```sql
SELECT COUNT(*) FROM sys.tables     WHERE is_ms_shipped = 0;
SELECT COUNT(*) FROM sys.views      WHERE is_ms_shipped = 0;
SELECT COUNT(*) FROM sys.procedures WHERE is_ms_shipped = 0;
```

…and compared the result to the count `SchemaReader` recorded at comparison time. SMO's `IsSystemObject` filter is **per-type and stricter** than `is_ms_shipped` alone: for **views and procedures** it also excludes objects carrying the `microsoft_database_tools_support` extended property. That property is exactly what SSMS attaches when you install **database-diagram support** — the `sysdiagrams` table plus `sp_creatediagram`, `sp_helpdiagrams`, `fn_diagramobjects`, and friends.

On any destination where diagrams have been installed, the raw catalog COUNT was N higher than the SMO snapshot, the "destination has changed" dialog fired on every Generate-Script / Apply-Live click, and the proc count was the loudest signal because diagram support adds several procs. (Tables didn't drift because SMO doesn't apply the extended-property check for tables — only views and procs.)

The verify query now applies the same per-type filter SMO does, so the counts always agree and the warning only fires when something actually changed.
