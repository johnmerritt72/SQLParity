# What's New in SQLParity 1.4.5

A new schema filter narrows comparisons to a single schema, speeding up scoped compares of large multi-schema databases.

## ✨ Added

### Schema filter for comparisons
A new **Schema:** dropdown at the bottom of the comparison setup screen (next to the object-type checkboxes) limits the comparison to a single schema.

The list is populated from Side A's selected database (system schemas excluded), and the same schema selection applies to both sides. The default **(All schemas)** keeps today's behavior — nothing changes unless you pick a schema.

Filtering happens at read time — objects in other schemas are never enumerated or scripted — so scoped compares of large multi-schema databases are substantially faster.

Works in folder mode too: Side B's parsed .sql objects are filtered in memory to match the selected schema.

Schema-scoped reads are cached separately from full-database reads (a scoped read can never be served as the whole database), and a fresh full-database cache entry satisfies a scoped compare instantly by filtering it in memory.

Permissions comparison scopes with the filter as well: object-level grants for objects in the schema, plus that schema's schema-level grants.

**Note:** with a filter active, objects in other schemas simply don't appear in results — they are not reported as missing.
